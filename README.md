# Единая цифровая диспетчерская УК

Один бот в MAX для жителей, операторов и исполнителей, с учётом заявок внутри.
Житель создаёт заявку в личном диалоге за четыре вопроса; сотрудники работают в том же боте. Веб-интерфейс и Mini App не разрабатываются.

Рабочий цикл: обращение из чата или новая заявка → назначение сотрудника →
«В работе», «Готово», «Не выполнено» или «Для выполнения нужно…» с пояснением.

## Состояние проекта

Реализованы разные личные режимы одного бота: житель, оператор и исполнитель.
Оператор получает диспетчерские очереди «Новые», «Без исполнителя», «В работе»,
«Требуют внимания», «Все заявки» и список исполнителей; из карточки заявки он
назначает активного исполнителя. Исполнитель видит только свои задания и отмечает
ход/результат работ. Неизвестный MAX ID получает простой поток
жителя: имя → полный адрес → что произошло → телефон → подтверждение/отмена,
а в «Мои заявки» видит только собственные заявки и их статус. В групповом чате
этот же бот отсекает обычный разговор по простому правилу и отправляет оператору
только MAX ID автора и текст возможной проблемы; заявка из чата автоматически не создаётся.

Внутри работают FastAPI, PostgreSQL и очередь ответов бота. Повторные события MAX
не создают дубликаты; права и исполнитель проверяются перед изменениями.
Справочники и начальные сотрудники настраиваются командой на сервере.
Доступ задаётся MAX ID в env: владельцы, операторы и исполнители разделены по ролям.
Токены и остальные настройки будут добавлены при деплое.

Код проверяется на синтетических событиях и отдельной тестовой БД. Реальная
доставка в MAX ещё не проверена. Эпики остаются открытыми до приёмки;
исходное большое ТЗ и план сохранены, текущий объём уточнён в описании бота.
Ранее созданные служебные API и вход по подписанным данным MAX сохранены.

## Начало работы

Для запуска следуйте [инструкции разработчика](docs/development.md).
Для тестов используются отдельные PostgreSQL и Redis; реальные чаты и токены
MAX не требуются. Следующая проверка при деплое — реальные личные сообщения, нажатия кнопок и чтение группового чата основным ботом.

Официальную заявку из обращения в чате создаёт уполномоченный сотрудник. Внутренние данные CRM доступны только сотрудникам в пределах их прав.

Секреты и рабочие данные не включаются в Git. Политика изменений и условия production-операций определены в `AGENTS.md`.
